## Open architectural and UI work

12. **P1: server-side concurrent writers.** `worker/index.ts:327-335` replaces a room snapshot
    with unconditional `kv.put`. Two clients can read the same base and overwrite one another.
    Client pull-before-push reduces stale writes but does not make this atomic. A serialized room
    authority or transactional version/CAS contract is required; do not promise conflict-free
    multi-writer synchronization from these client patches.
13. **P2: schema validation.** `syncApi.ts:76-80` only checks the tools array and truthiness of two
    metadata fields. Missing or malformed personnel/orders/settings can then fail in the merge.
    The Worker checks only JSON syntax. Introduce a versioned boundary validator/migration contract.
14. **P2: global persistence/error semantics and payload growth.** `Store.save` rewrites all stores;
    most non-calibration mutations edit memory before persistence. A failed write can leave memory
    ahead of disk. The order path now rolls back, but a general mutation/commit policy is still
    needed. `photos.ts:21,57-65` declares a five-photo limit without enforcing it and embeds image
    bytes in tool snapshots. The Worker fallback map is unbounded. These are real growth paths;
    no browser heap-leak diagnosis is claimed.
15. **P2/P3: UI accessibility and contract drift.** Most modal roots lack dialog semantics, focus
    trapping and focus restoration; labels frequently lack a control association. Several runtime
    captions remain hardcoded English. EN/RU key parity does not measure translated-string coverage.
    The v133 zero-any claim is stale: baseline `rg` found 26 matching source lines (including comments).
    Do not treat that count as a runtime defect or as 26 separate bugs.

The previously accepted open room-key API model was not reopened as a new finding.

## Verification and limits

- Baseline application tests: 177 passing. New baseline sync invariants: 5 failures in 5 probes.
- Candidate: 198 passing tests, TypeScript, ESLint, EN/RU key parity 726/726, production build,
  PWA first-install offline bootstrap, and the browser audit regression script.
- Real Chromium probes verify prompt cancellation, cancelled/invalid receipts, zero stock,
  serial form population, privileged continuation, SOP event-handler sanitization, mandatory
  gate retention and certificate download. PDF text extraction verifies Cyrillic and all 40
  repeated note segments plus the final marker; rendering was inspected.
- Four viewport procurement checks and 4/12-document SOP hub checks were completed in the
  preceding v134/v135 work. Physical printers, real calibration hardware, multi-day background
  suspension, simultaneous live Cloudflare writers and exhaustive assistive-technology testing
  were not exercised here.
- `npm audit --omit=dev`: baseline 1 critical + 8 moderate package findings; candidate 0 critical
  + 8 moderate after the DOMPurify update. This is dependency metadata, not proof that every
  listed advisory is exploitable in this browser configuration. Do not apply a forced ExcelJS
  downgrade as an automatic remediation.

The candidate changes room-join behavior deliberately: the departing room is archived locally;
its inventory is not imported into another room. An existing cached state of the target room is
merged only with that same room. Review that behavior before production rollout.
